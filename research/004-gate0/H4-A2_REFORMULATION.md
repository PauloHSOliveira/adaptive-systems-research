## 1. Precise question

Can two permutations of the **same benign insertion multiset**, with fixed CMS hashes, cause a fixed feedback-adaptive attacker to choose **different adversarial insertions** and therefore produce different **final target-frequency estimation errors**?

This concerns how public observations **mediate the attacker's future actions**; it is not a claim that classical CMS is intrinsically sensitive to update ordering.

## 2. Algebraic structural control

For insertion-only Count-Min Sketch with fixed hashes, row j, bucket b contains

\[
C_{j,b}(f)=\sum_x f_x\mathbf 1[h_j(x)=b],
\qquad
\widehat f(x;f)=\min_j C_{j,h_j(x)}(f).
\]

**Lemma (standard order invariance):** Same complete final frequency vector and same hash functions imply bit-identical final bucket states and point-query results. Each bucket is a commutative sum of final frequencies. QED.

Therefore two permutations of the same complete stream, **including identical attacker-generated insertions**, have equal final results. A nonzero terminal difference requires a changed final frequency vector, e.g., **different adversarial insertions selected through feedback**. This is an elementary sanity check, not new theory.

## 3. Experimental intervention and adversary model

**Sketch:** A pinned conventional fixed-hash CMS, insertion-only unit updates, no decay, no resets, no conservative-update rule, and no counter overflow. Wider/protected CMS is a separate reference condition.

**Hash assumption:** Declare one model. For a first replication-oriented study, independent seeded hash functions whose seeds are hidden from the policy can be used; **a hidden seed alone is not cryptographic security or a random oracle**. Compare public-hash and idealized/random-oracle models only as explicitly separate conditions.

**Target:** Preselect identifier x* **before** drawing hash seeds or stream samples; ban x* from benign and adversarial inserts. Then its true final frequency is zero and an estimate above zero represents collision overestimation.

**Benign input:** For each seed, generate exactly one multiset of m_b honest insertions. Construct two predeclared orders:

- **P0:** Interleaved groups / stationary-looking temporal distribution.
- **P1:** Two phases with different dominant key groups / bursty temporal distribution.

Their total benign counts per key must agree exactly. These are controlled **permutations**, not independently drawn streams and not evidence of general concept drift.

**Attack policy:** One fixed program pi receives only the public answer to its own queries, may choose subsequent permitted insertions, and uses only causal history. If it maintains past observations, account for its persistent transcript size: **do not label it memoryless**. It never sees the hash internals, a future benign input, or exact oracle counts.

**Same budgets:** Match number of adversarial insertions, public query opportunities, and query timing rules across both conditions. Save the precise realized action trace and RNG states for independent replay. The old 256-query/10,000-insertion settings are **tentative and not validated**; choose budgets only from a separated feasibility pilot and freeze them before confirmatory testing.

### Required controls

- **A0, precommitted:** The attack's entire insertion multiset and query schedule are fixed without reading sketch outputs. The terminal A0 result **must be equal under P0 and P1**, with hash seeds held fixed.
- **A1, feedback-adaptive:** Same executable policy pi, seed, budget and public-query schedule for P0 and P1. The attack's inserted keys **may** differ as a result of feedback.
- **A2, frozen replay:** Replay exactly the adversarial keys generated by A1 in one ordering against the other benign ordering, without adapting. With identical complete multisets, the final CMS states **must agree**. This verifies the mediation mechanism; it is not an independent attack.
- **A3, no attack:** Optional sanity check on errors caused only by honest updates.

## 4. Primary metric and estimand

After exactly M total insertions, let

\[
Y(P,A,s)=\frac{\widehat f_M(x^*;P,A,s)-f_M(x^*;P,A,s)}{\max(1,\|f_M(P,A,s)\|_1)}.
\]

The target is forbidden from all insertions, so its true frequency equals zero. Fixed insertion budgets preserve the denominator. If some policy ends early, do not silently pad: declare a precommitted padding mechanism and validate that it does not change the target's estimate, or redesign the metric.

The paired seed-level interaction is

\[
d_s=[Y(P1,A1,s)-Y(P1,A0,s)]-[Y(P0,A1,s)-Y(P0,A0,s)].
\]

By the order-invariance lemma, the A0 difference is **exactly zero** per seed, so this reduces to the difference between feedback-adaptive terminal outcomes under two benign permutations.

**Hypothesis:** The expected paired difference is materially nonzero for a preregistered, reproducible attack policy. The *sign* must be chosen based on independent prior knowledge; if unknown, preregister a two-sided alternative rather than selecting the favorable sign after evaluation.

**Independent sampling unit:** the full paired RNG/hash/benign-multiset seed. Within-stream queries and checkpoints are correlated and are not independent replicates.

**Secondary metrics:** cover-set discovery probability, query efficiency, attacker memory, different selected keys, independent benign probes, CMS counter bytes, update CPU, and outcome sensitivity across a *predeclared* short list of workloads.

## 5. Existing work and novelty limitations

- **CCS 2023** has already demonstrated CMS adaptive cover-finding and Count-Keeper mitigation, as confirmed by pinned scripts [here](https://github.com/smarky7CD/cfe-in-adv-envs/tree/5e511f60015c2c1d3a10a950d94c58d2c988cc46/experiments/attacks).
- A **related anonymous CMS manuscript** at [OpenReview](https://openreview.net/pdf?id=IuEBdNsWKb) details theorems for robust row/bucket choices, value-based adaptive cover attacks, heavy update weights and query-efficiency experiments. Its identity with the definitive **KDD 2025** paper is **not yet authenticated**; see [technical-source audit](KDD_PREPRINT_AUDIT.md).
- **NDSS 2023** already addresses temporal frequency-distribution variation, and **NDSS 2026** already addresses different benign background contexts against adaptive heavy-hitter monitoring attacks. This H4-A2 question is narrower, and still may not be original.
- A CMS correctly configured for a known strong adversarial robustness theorem might show **no meaningful attack effect**. Do not frame a null result in that condition as an implementation flaw.
